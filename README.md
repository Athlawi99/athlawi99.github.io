# جسر — دليل التركيب

صفحة تنقل بها النصوص والملفات بين جوالك وأي كمبيوتر، تفتحها بعبارة سرية فقط بلا أي حساب.
كل شيء يُشفَّر داخل المتصفح قبل أن يُرفع، فحتى الخادم لا يرى محتواك.

يحتاج التركيب نحو 15 دقيقة، ويتم مرة واحدة فقط. الأفضل أن تنفذه من كمبيوتر.

---

## الخطوة 1: حساب GitHub (هو الذي يحدد عنوان صفحتك)
1. ادخل github.com وأنشئ حسابًا، أو استخدم حسابك الحالي.
2. **اسم المستخدم هو عنوان صفحتك**: إذا كان اسمك `fahd-jisr` فسيكون العنوان `fahd-jisr.github.io`.
   اختر اسمًا قصيرًا يسهل حفظه. إذا كان اسم حسابك الحالي طويلًا، أنشئ حسابًا جديدًا لهذا الغرض.

## الخطوة 2: إنشاء المستودع
1. اضغط **+** أعلى الصفحة، ثم **New repository**.
2. في **Repository name** اكتب بالضبط: `اسمك.github.io` (مثال: `fahd-jisr.github.io`).
3. اختر **Public**، ثم اضغط **Create repository**.

## الخطوة 3: قاعدة البيانات المجانية (Supabase)
1. ادخل supabase.com، ثم اضغط **Start your project** وسجّل الدخول بحساب GitHub نفسه.
2. اضغط **New project**:
   - Name: `jisr`
   - Database Password: اضغط **Generate** واحفظها في مكان ما (لن تحتاجها غالبًا)
   - Region: اختر أقرب منطقة لك
3. اضغط **Create new project** وانتظر دقيقة أو دقيقتين حتى يجهز.

## الخطوة 4: تجهيز الجداول
1. من القائمة الجانبية افتح **SQL Editor**.
2. افتح ملف `setup.sql`، وانسخ محتواه كاملًا والصقه هناك.
3. اضغط **Run**. يجب أن تظهر كلمة **Success**.

## الخطوة 5: نسخ المفاتيح إلى config.js
1. افتح **Project Settings** (رمز الترس)، ثم **API Keys** أو **Data API**.
2. انسخ قيمتين:
   - **Project URL**، وتبدو هكذا: `https://abcd1234.supabase.co`
   - **Publishable key**، أو المفتاح المكتوب عليه **anon / public** في الإصدارات الأقدم
3. افتح ملف `config.js` في المفكرة (Notepad) وضع القيمتين مكان `XXXXXXXX` و`ضع_المفتاح_هنا`، مع إبقاء علامات التنصيص كما هي.

> لا تستخدم المفتاح السري (`service_role` / `secret`) أبدًا. المطلوب هو المفتاح العام فقط.

## الخطوة 6: رفع الملفات إلى GitHub
1. افتح المستودع الذي أنشأته، ثم اضغط **uploading an existing file** (أو **Add file ← Upload files**).
2. اسحب هذه الملفات الأربعة: `index.html` و`config.js` و`setup.sql` و`README.md`، ثم اضغط **Commit changes**.
3. ملف الإبقاء على النشاط: اضغط **Add file ← Create new file**.
   - اكتب اسم الملف بالضبط: `.github/workflows/keepalive.yml`
   - الصق فيه محتوى ملف `keepalive.yml` الموجود داخل مجلد `.github/workflows`
   - اضغط **Commit changes**.

## الخطوة 7: تشغيل الصفحة
1. في المستودع افتح **Settings**، ثم **Pages**.
2. في **Source** اختر **Deploy from a branch**، والفرع **main** والمجلد **/ (root)**، ثم اضغط **Save**.
3. انتظر دقيقة أو دقيقتين، ثم افتح: `https://اسمك.github.io`

## الخطوة 8: تجربة الإبقاء على النشاط (مرة واحدة)
1. افتح تبويب **Actions** في المستودع، ووافق على التفعيل إن طُلب منك.
2. اختر **keepalive**، ثم **Run workflow**. يجب أن تظهر علامة صح خضراء.

السبب: مشروع Supabase المجاني يتوقف تلقائيًا بعد أسبوع بلا استخدام، وهذا الملف يزوره كل 3 أيام حتى يبقى شغالًا.

---

## الاستخدام
- **العبارة السرية** هي مفتاح درجك. نفس العبارة تفتح نفس الدرج من أي جهاز.
  اجعلها من 3 كلمات أو أكثر، مثل: `قهوة صبيا الساعة سبعة`. وإذا نسيتها فلا توجد طريقة لاسترجاع المحتوى.
- **في الكمبيوترات العامة**: لا تفعّل «تذكرني»، واضغط **خروج** عند الانتهاء. ولو نسيت، يُقفل الدرج تلقائيًا بعد 15 دقيقة بلا نشاط.
- الملفات المنزّلة تبقى في مجلد التنزيلات في الكمبيوتر العام، فاحذفها بعد الاستخدام.
- **الحذف التلقائي**: خيار «احذف ما أرسله تلقائيًا بعد يوم» مفعّل افتراضيًا، والصفحة تتذكر اختيارك. وفي الدرج زر «حذف الكل» يمسح كل شيء بضغطتين.
- **الحدود المجانية**: 49 ميجابايت للملف الواحد، و1 جيجابايت مساحة كلية. احذف القديم أولًا بأول.
- **إذا ظهرت رسالة «تعذر الاتصال بالخادم»**: ادخل supabase.com وافتح المشروع، وإذا كان متوقفًا اضغط **Restore**.
